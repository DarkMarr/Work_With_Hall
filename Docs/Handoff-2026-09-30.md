สรุปสิ่งที่ทำไปในรอบนี้ และสิ่งที่ยังเหลือ เรียงตามความสำคัญ

## อัปเดต HALL900 รอบ Lucky Draw / Item

- Compile ผ่านหลังย้ายการสร้าง controller 4 ตัวใน `MainMenuController` จาก field initializer ไป `Awake()`; ทดสอบสร้าง component แล้วไม่เกิด Unity API constructor error
- ผลจำลอง (`standin-*`) แสดง Result และ Lucky Draw เพื่อทดลองได้ แต่ขึ้นคำว่า Preview ชัดเจน และ **ไม่บันทึก inventory/RP** ทั้งใน UI และชั้น `PlayerDataManager`
- `SetStandInResults()` ส่ง event ครั้งเดียวหลังตั้ง `IsFromServer = false` แล้ว ปิดช่วงสั้น ๆ ที่ listener เคยมองผลจำลองเป็นผล server
- ทดสอบ Play Mode แยกครบอันดับ 1–4: ปุ่ม Draw รับคลิกครั้งเดียว, animation ผ่าน Ready → WindUp → Spinning → BallDrop → Reveal, หน้าผลมีปุ่ม Accept และกดได้
- snapshot ผู้เล่นและจำนวน receipt ใน Firebase Emulator ก่อน/หลังการหมุนจำลองเหมือนเดิม
- ทดสอบ transaction ใน Firebase Emulator: claim แรกได้ item `+1`, RP `+10`, gamesPlayed `+1`; retry match id เดิมด้วยจำนวน/อันดับอื่นไม่เพิ่มซ้ำ; `standin-*` ถูกปฏิเสธ
- ไอเท็ม Fashion ที่ยังไม่มี localization ใช้ชื่อ set ที่อ่านได้ชั่วคราว จึงไม่ throw `Empty Table Reference` และไม่ค้างที่ `Item Name`
- เพิ่ม offline regression check ที่ `HALL900/Testing/Check Lucky Draw Safety (Offline)` ตรวจ preview/server isolation, snapshot copy, stand-in claim guard และชื่อ Fashion reward 22 ชุด
- เพิ่มเอกสารเทียบ Google Sheet ที่ `Docs/Item-Reference-2026-09-30.md`

สิ่งที่ยังต้องทำ: room adapter จริงต้องส่งผล server และ backend ต้องตรวจ match/result/reward อย่าง authoritative; client guard รอบนี้กันการบันทึกจาก preview เท่านั้น ไม่ใช่ระบบป้องกันโกง. ค่า material quantity `1` ยังรอ game designer ยืนยัน. Result fixture พบ cat/dog บางตัวเหลือเพียงส่วนของภาพ เพราะปัญหา PSB crop ในข้อ 1 ไม่ใช่โค้ด Result.

## 1. Character PSB ยังไม่เป็น 600×600 — งานศิลป์ ยังไม่เสร็จ

**นี่คืองานที่บล็อกเรื่อง fashion ทั้งหมด**

รายละเอียดเต็มอยู่ใน `Docs/Character-PSB-Export-Spec.md` อ่านอันนั้นก่อน

สถานะล่าสุดหลัง export รอบวันที่ 30 ก.ย.:

| ไฟล์ | ผล |
| --- | --- |
| `UC_rabbit_*` ทั้ง 4 | 3.00 × 3.00 ✅ |
| `UC_cat_Mint` | 2.24 × 1.60 ❌ |
| `UC_dog_Milo` | 1.48 × 1.38 ❌ |
| `R_cat_Callie` | 1.43 × 1.39 ❌ |

rect ใน PSB ที่ export ใหม่ยังเป็น `78×88`, `276×86`, `214×67` ไม่ใช่ `600×600`

**ตรวจแล้วว่าไม่ใช่เรื่องตั้งค่า** — เทียบ `UC_rabbit_Momo.psb.meta` กับ `UC_cat_Mint.psb.meta`
แบบ byte ต่อ byte เหมือนกันทุกบรรทัด ต่างแค่ GUID

สาเหตุ: Unity PSD Importer **ตัดเลเยอร์ชิดขอบพิกเซลทึบอัตโนมัติ** เลเยอร์ที่มีขอบโปร่งใส
จะโดน crop เสมอ ต้องมีเนื้อหาแตะขอบ canvas

**วิธีแก้:** ใส่ fill เต็มผืน 600×600 ที่ **alpha 1/255** ในทุกเลเยอร์ (ตามองไม่เห็น แต่พอกัน
importer ไม่ให้ crop) แล้วเช็คใน Sprite Editor ว่าทุก rect อ่าน `600 x 600`

**สองไฟล์นี้ยังไม่ถูกแตะเลย** (ยังเป็นของ 4 ก.ย.) และเป็นไฟล์ที่ prefab ใช้จริง:
- `Assets/Art/Sprites/Char/002_Cat_04072026.psb`
- `Assets/Art/Sprites/Char/003_Dog _04072026.psb`

> ⚠️ **ห้ามสร้างไฟล์ PSB ใหม่** sprite ID มาจาก layer ID ของ PSD สร้างใหม่ = prefab หลุด
> reference เงียบ ๆ ทั้งหมด (PSB แมวไฟล์เดียวมี 397 เลเยอร์) ให้แก้ไฟล์เดิมเท่านั้น

## 2. Lucky Draw — flow ทดสอบแล้วใน Play Mode fixture

อาการเดิม: ตอบคำถามจบแล้วไม่ขึ้นหน้า Lucky Draw

มี **3 ด่าน** ที่บล็อกพร้อมกัน แก้ครบทั้งสามแล้ว และทดสอบ flow แยกโดยไม่แตะ production data

### ด่าน 1 — `luckyDrawMaterialQuantity` เป็น 0

`GameplayController.cs:500` ตัดจบทันทีถ้าค่านี้ ≤ 0

**แก้แล้ว:** ตั้งเป็น `1` ใน `Assets/Scenes/Gameplay.unity`

> 🔸 **เลข 1 เป็นค่าชั่วคราวที่ผมตั้งเอง** ไม่ได้มาจากเอกสารออกแบบ
> ต้องให้คนออกแบบเกมยืนยันว่าดรอป "เทา" (material) ควรได้กี่ชิ้นต่อครั้ง

### ด่าน 2 — ทุก destination ขาด pool Rare / Uncommon / Common

ของเดิมมีแต่ `TestDecoration*` (SuperRare ล้วน) กับ `TestEquipment*` (NoTier ล้วน)

`LuckyDrawRules.Choose()` **ตั้งใจคืน null** เมื่อ pool ไหนว่าง เพราะการ reroll ข้ามระดับ
จะทำให้อัตราดรอปที่ประกาศไว้เพี้ยน (ดูคอมเมนต์ `LuckyDrawRules.cs:48`)

**แก้แล้ว:** เมนูใหม่ `QuizGame/Setup/Create Fashion Reward Items + Fill Destination Pools`
สร้าง `EquipmentItemSO` 22 ตัวจาก fashion set แล้วใส่เข้า pool ของแต่ละเมือง

- `Fashion_R_<เมือง>` → เข้าเฉพาะเมืองนั้น (tier = Rare)
- `Fashion_UC_<เมือง>` → เข้าเฉพาะเมืองนั้น (tier = Uncommon)
- `Fashion_C_*` 6 ชุด → เข้าทุกเมือง (tier = Common)
- `Fashion_SR_*` 4 ชุด → เข้าทุกเมือง (tier = SuperRare)

รันแล้วได้ `all pools filled` ครบ 6 เมือง และจำลองการสุ่ม 4,800 ครั้ง (6 เมือง × 4 อันดับ ×
200 ครั้ง) **ไม่มี null สักครั้ง**

เมนูรันซ้ำได้ ของเดิมจะถูก update ไม่สร้างซ้ำ และจะเก็บ equipment ที่ใส่มือไว้ไม่ทับ

> `EquipmentItemSO.itemID` ตั้งให้เท่ากับ id ของ fashion set เลย (`Fashion_C_Baseball`)
> เวลาได้ของรางวัลจึงหาชุดกลับได้ด้วย `FashionResourceManager.GetResource(id)`
> โดยที่ assembly `Item` ไม่ต้องรู้จัก `Character`

### ด่าน 3 — `IsFinal` เป็น false ตลอด ⬅ ตัวจริง

**นี่คือด่านที่บล็อกก่อนสองด่านบนด้วยซ้ำ**

`MultiplayerResultReceiver.BeginMatch()` กับ `SetFinalResults()` **ไม่มีใครเรียกเลยทั้งโปรเจกต์**
เป็น seam ที่รอ room adapter ซึ่งยังไม่มี ผลคือ `IsFinal` เป็น false เสมอ →
`GameplayController.cs:484` ตัดจบที่ "Results pending — Waiting for the final scores of all
players" แล้วเด้งกลับ Main Menu ทุกครั้ง

**แก้แล้ว:** เพิ่ม `MultiplayerResultReceiver.SetStandInResults()` ปิดแมตช์ด้วยคะแนนที่ประกอบ
ในเครื่อง ใช้แพตเทิร์นเดียวกับ `MultiplayerRoster`:

- คะแนนของเราเป็นของจริง คะแนนคู่แข่ง 3 คนสุ่มรอบ ๆ คะแนนเรา
- ใช้ชื่อกับตัวละครจาก `MultiplayerRoster` ตัวเดียวกับที่ lobby และในแมตช์แสดง
- **สุ่มอันดับก่อน แล้วค่อยสร้างคะแนนรอบอันดับนั้น** ไม่ใช่สุ่มคะแนนแล้วดูว่าได้อันดับอะไร
  วิธีหลังดูยุติธรรมกว่าแต่ไม่ใช่ — การจะได้ที่ 1 หรือที่ 4 ต้องให้คู่แข่งตกไปข้างเดียวกันหมด
  ซึ่งเกิดแค่ ~5% (วัดจริงแล้ว: ที่ 1 ได้ 27 จาก 600 ครั้ง) ทำให้เทสไม่เคยเจออันดับหัวท้าย
  ทั้งที่อันดับเป็นตัวกำหนด RP และอัตราดรอป
- **คะแนนห้ามซ้ำและห้ามติดลบ** `OpenMultiplayerRewards` ปฏิเสธอันดับเสมอ และ `SetResults`
  ปฏิเสธคะแนนติดลบ ทั้งคู่ทำให้ Lucky Draw หายไปอีก จำนวนคู่แข่งที่อยู่ใต้ผู้เล่นจึงถูกจำกัด
  ด้วยคะแนนจริงที่มี (`below = min(ที่ต้องการ, คะแนนผู้เล่น)`) คนที่ได้ 0 คะแนนจึงได้ที่ 4 เสมอ
  ซึ่งก็ถูกต้องตามความจริง

**ทดสอบแล้ว** (ไม่ใช่ play mode แต่เรียก `SetStandInResults` จริง 600 ครั้งต่อกรณี):

| คะแนนผู้เล่น | อันดับ 1/2/3/4 | refused | ties | ติดลบ | ซ้ำ |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 / 0 / 0 / 600 | 0 | 0 | 0 | 0 |
| 1 | 0 / 0 / 451 / 149 | 0 | 0 | 0 | 0 |
| 2 | 0 / 297 / 149 / 154 | 0 | 0 | 0 | 0 |
| 8-20 | 128 / 172 / 167 / 133 | 0 | 0 | 0 | 0 |
- `IsFromServer` เป็น false เมื่อใช้ค่าปลอม — อะไรที่จะรายงานอันดับว่าเป็นทางการ
  (leaderboard, การแจ้งเปลี่ยนแรงก์) ต้องเช็คตัวนี้ก่อน
- `SetStandInResults` **ปฏิเสธการเขียนทับ snapshot จริง** ต่อเซิร์ฟเวอร์แล้วจึงไม่ตีกัน

**เวลาต่อเซิร์ฟเวอร์จริง:** ให้ room adapter เรียก `BeginMatch()` ตอนเริ่มแมตช์ และ
`SetFinalResults()` เมื่อได้ผลครบทุกคน แล้ว**ลบการเรียก `EnsureStandInResults()`
ใน `GameplayController.OpenRewardUI()` ทิ้งจุดเดียว** จบ
